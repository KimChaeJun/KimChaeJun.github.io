# 직접 실행한 프로젝트 화면 기록

촬영일: 2026-11-10 (Asia/Seoul).

LyriKana와 119 보이는 ARS의 기존 로컬 실행 코드를 사용해 실제 창과 브라우저 화면을 촬영했습니다. 화면을 재현한 HTML이나 생성 이미지를 사용하지 않았고, 캡처 원본 JPEG를 편집 없이 추가했습니다. 두 저장소 모두 저장되지 않은 로컬 변경이 있어, 기준 커밋이 실행 코드 전체와 일치하지 않습니다. [실행 파일 해시](project-runtime-versions.json)와 [캡처 파일 해시](project-media-sources.json)를 함께 기록했습니다. 두 프로젝트의 소스 변경은 수정·커밋·배포하지 않았습니다.

## LyriKana — 2장

- 기존 Python 가상환경으로 FastAPI를 127.0.0.1:8000에 실행하고, 별도 시연용 SQLite DB를 사용했습니다.
- 설치된 Electron 앱을 별도 user-data-dir로 실행했습니다. 창은 운영체제 크기 조절 메뉴로 확대했습니다.
- 직접 작성한 일본어 예문을 기존 로컬 API로 전달했습니다. 실제 노래 가사를 가져오지 않았습니다.
- /reading/sudachi/analyze에서 朝の光が窓を照らす의 읽기 あさのひかりがまどをてらす 응답을 확인했습니다.
- /overlay에는 원문·읽기·한글 발음·다음 줄을, /settings에는 언어·테마·글씨 크기·불투명도를 전달했습니다. 한글·로마자 발음 문자열은 시연 입력입니다.
- 한국어 발음과 어두운 테마, 로마자 발음과 밝은 테마의 실제 실행 창을 각각 캡처했습니다.
- 실제 재생 버튼을 클릭한 뒤 /player/commands/poll에서 play-pause 명령을 확인했습니다. 이는 명령 큐까지의 검증입니다.
- Ctrl+Alt+L로 클릭 통과 상태가 ON/OFF로 바뀌는 것을 확인하고 원래 상태로 되돌렸습니다. 클릭 통과 상태의 화면은 게시하지 않았습니다.
- 미검증: YouTube Music 연결, 실제 음악 재생·일시정지·탐색과 가사 동기화, 확장 프로그램 설정 화면, GPU 음원 분석.

## 119 보이는 ARS — 4장

- 기존 Python 가상환경과 Vue/Vite 앱을 127.0.0.1:8010, 127.0.0.1:5190에서 실행했습니다.
- 별도 시연용 SQLite DB와 로컬 영상 카탈로그를 사용했습니다. 원격 카탈로그는 비활성화하고 문자 공급자는 mock으로 설정했습니다.
- 01000000000, 시연용 교육센터 1층, 포트폴리오 시연이라는 테스트 정보로 UI에서 세션을 생성했습니다.
- UI의 연결 링크를 별도 브라우저 탭에서 열어 모바일 연결 및 WebSocket 연결 상태를 확인했습니다.
- 가슴압박 CPR 영상을 선택·전송하고 상황요원의 다음 버튼으로 1/4 → 2/4 변경을 확인했습니다.
- 신고자 화면에서 해당 영상의 readyState=4, duration=108.1, currentTime=13을 확인했습니다. 캡처 시 paused=true였으므로 지속 재생·음성 출력 성공으로 기록하지 않습니다.
- 신고자 화면은 390×844 뷰포트에서 촬영했습니다. 실제 휴대폰 촬영은 아닙니다.
- 접수 양식, 상황요원 대시보드, 신고자 안내, 등록 영상 7개와 입력 양식이 있는 영상관리 화면을 캡처했습니다.
- 화면의 추천율·위험도·출동·병원 정보는 앱이 표시하는 시연용 데이터입니다. 실제 신고·환자·기관 운영 데이터가 아닙니다.
- 미검증: 실제 문자 발송, 음성 STT, 카메라·WebRTC, 실제 휴대폰, 중앙 영상 저장소 연결, 새 영상 업로드.

## 반영과 보존

- 기존 산재원샷 및 다른 프로젝트 자료·순서는 보존합니다.
- 관리자 CMS에는 새 media 항목만 추가하며, 기존 문구와 프로젝트 정보는 바꾸지 않습니다.
- Tickget은 사용자가 자료를 찾기로 했으므로 추가 조사·변경하지 않았습니다.
- [남은 촬영 목록](project-media-checklist.md)을 최신 상태로 갱신했습니다.
