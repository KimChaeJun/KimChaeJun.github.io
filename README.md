# 김채준 포트폴리오

React + Vite로 만든 GitHub Pages 포트폴리오입니다. Sanity의 발행된 콘텐츠를 읽습니다. 연결 실패 시 재시도 안내를 표시하며, 삭제된 프로젝트를 기본 데이터에서 다시 불러오지 않습니다.

## 콘텐츠 기준

기존 산재원샷·LyriKana에 119 보이는 ARS, 흡연·건강지표 분석 대시보드, 대사증후군 위험군 분석, 건강관리 실습 앱, AI Health Web Service, POCKET SSAFY, SPOANY, Tickget을 추가했습니다.

- 각 저장소 기본 브랜치 루트의 정확한 `timeline.md`에서 공개용으로 정리한 내용만 반영했습니다.
- 새 8개 프로젝트의 미확인 개인 역할·기여·참여 기간·수상·성과 수치는 빈 값으로 유지하고 해당 화면을 숨깁니다.
- 새 프로젝트와 LyriKana의 연혁은 코드 변경 기록일입니다. 참여 기간이나 실제 배포일로 해석하지 않습니다.
- 건강관리 실습 앱은 제공된 완성 예제·실습 코드라는 맥락을 유지합니다. 분석·의료 관련 프로젝트에 검증되지 않은 임상 성능이나 인과관계를 부여하지 않습니다.
- 비공개 소스코드·내부 경로·인증 정보는 공개 데이터에 포함하지 않습니다.

## 관리자 모드

운영 사이트 하단 **관리자 모드** 또는 [관리자 주소](https://kimchaejun.github.io/admin/)로 이동합니다.

1. GitHub로 Sanity에 로그인합니다. `KimChaeJun Portfolio` 프로젝트 구성원만 접근할 수 있습니다.
2. 실제 홈페이지 미리보기의 점선 문구를 클릭합니다. 왼쪽 목록에서도 프로필·홈페이지 문구·프로젝트 항목을 선택할 수 있습니다.
3. 텍스트를 수정합니다. 발행 전에는 이 관리자 화면에서만 미리 보이며, **변경 취소**로 되돌릴 수 있습니다.
4. **발행**을 누르면 방문자 화면에 반영됩니다. 문구만 바꾸는 작업에는 Git 커밋이나 사이트 재배포가 필요하지 않습니다.

프로필·프로젝트의 **추가 역할 태그**에서 AI PM을 선택할 수 있습니다. 기본은 미선택이며 Full Stack Developer가 있으면 FE·BE·Infra 역할 중복 표시는 생략합니다.

발행된 콘텐츠는 Sanity의 `production` 데이터셋, `portfolio` 문서의 `content` 필드에 저장합니다. 데이터셋은 공개 읽기이며 수정은 Sanity가 인증·권한을 검증합니다. 프로젝트 ID는 공개 식별자이고, 쓰기 토큰을 사이트 번들·GitHub Secrets에 넣지 않습니다. 로그인은 공식 Sanity Studio가 처리합니다.

수정 충돌을 감지하면 발행을 거부하고 작성 내용을 화면에 유지합니다. 해당 문구를 복사해 보관하고 변경을 취소한 뒤 **최신 콘텐츠 다시 불러오기**를 이용하세요. 입력한 미발행 변경은 브라우저를 닫으면 사라집니다. URL·이메일·날짜 형식 오류와 허용하지 않은 필드 변경도 차단합니다.

같은 출처의 관리자 iframe만 미리보기 메시지를 주고받습니다. 프로젝트 주소(slug)와 연혁 기준은 관리자 텍스트 편집으로 바뀌지 않습니다. 프로젝트 추가·삭제·복원·순서 변경은 관리자 화면의 **프로젝트 관리**에서 처리합니다. 기술 그룹·연혁 등 세부 항목 구조 확장은 별도 데이터 작업으로 처리합니다. CMS의 기존 내용을 기본 데이터로 무조건 덮어쓰지 마세요.

### 프로젝트 관리

- **프로젝트 추가**: 이름과 고유 주소를 입력하고, 소개·설명·기술·역할·기간은 확인된 내용만 입력합니다. 입력하지 않은 수상·성과·연혁을 자동 생성하지 않습니다.
- **↑ 위로 / ↓ 아래로**: 메인, 프로젝트 목록, 프로젝트 선택 목록의 노출 순서를 변경합니다. 연혁 자체는 날짜순으로 유지됩니다.
- **삭제**: 삭제 확인 후 휴지통으로 이동합니다. **발행** 전에는 방문자 화면에 영향을 주지 않습니다.
- **휴지통 → 복원**: 프로젝트를 원래 내용 그대로 목록 마지막에 복원합니다. 필요한 위치로 이동한 뒤 발행하세요.
- **변경 취소**: 발행 전 추가·삭제·재정렬·텍스트 변경을 함께 취소합니다. 작성 중인 추가 폼도 비웁니다.
- 모든 프로젝트를 삭제할 수 있습니다. 빈 목록을 발행해도 코드의 기본 프로젝트가 다시 노출되지 않습니다.
- 휴지통은 사이트 목록에서 숨기는 복원용 보관함입니다. 공개 읽기 데이터셋 안에 보관되므로 민감정보 제거용 영구 삭제 기능은 아닙니다.

### AI 협업 기록

프로젝트의 `aiCollaboration`에는 사례별 `title`, `tools`, `stage`, `problem`, `approach`, `humanReview`, `outcome`, `evidence`를 저장합니다. 메인 선택 영역·프로젝트 카드·상세·Markdown 내보내기가 같은 데이터를 사용합니다. 관리자 텍스트 목록의 **AI 협업 사례**에서 각 문구를 수정할 수 있습니다. 사례 목록의 추가·삭제는 다른 세부 목록과 마찬가지로 별도 데이터 작업입니다.

제품 안에서 호출하는 AI 기능과 개발자의 AI 도구 사용은 구분합니다. 문서 작성·정리 사례를 개발 당시 AI 코딩 경험으로 확장하지 않습니다. 사용자에게 확인할 항목은 [AI 활용 보완 목록](docs/ai-collaboration-follow-up.md)에 정리했습니다. `timeline.md` 공개 JSON에도 같은 필드를 사용하며, 문서 변경이 CMS에 자동 발행되지는 않습니다.

`studio/scripts/merge-ai-collaboration.ts`는 최초 AI 필드 추가용입니다. 기본 실행은 현재 문서의 검토용 변경안을 `.ai-collaboration.local/`에 저장합니다. `-- --apply`를 전달하면 동일 revision·동일 변경안에 한해 해당 필드만 추가합니다. 기존 AI 필드가 있으면 덮어쓰지 않고 중단합니다. 프로필·순서·휴지통·기존 프로젝트 문구를 seed 데이터로 교체하지 않습니다.

## 화면과 탐색

- `#/`: 소개, 프로젝트별 AI 협업 사례, 10개 프로젝트, 최근 작업 기록
- `#/projects`: 기술 분야 필터, 구성도, 확인된 프로젝트 설명
- `#/projects/{slug}`: 기술, 개요, AI 활용 과정, 개인 기여·성과·개선 기록(있는 경우), 전체 연혁
- `#/timeline`: 전체 코드·작업 기록, 공개용 Markdown 다운로드
- `#/about`: 소개·주력 기술·확인된 프로젝트 경험, 인쇄/PDF
- `#/contact`: 실제 등록한 연락 채널
- `/admin/`: Sanity 로그인과 홈페이지 편집

`Ctrl+K` / `⌘K` 또는 상단 터미널로 이동할 수 있습니다. 기술 아이콘은 호버·키보드 포커스·터치로 이름을 표시하며 인쇄 시 이름을 함께 표시합니다. 로고 출처는 `public/icons/technology/README.md`를 참고하세요. 등록되지 않은 기술에는 공통 코드 아이콘을 사용합니다.

## 개발과 배포

```bash
npm ci
npm ci --prefix studio
npm run dev
npm test
npm run build
```

`npm run build`는 사이트, 관리자 타입 검사, 관리자 정적 번들을 순서대로 실행합니다. 사이트는 `dist/`, 관리자는 `dist/admin/`에 생성됩니다. Sanity CLI의 `project.basePath`가 관리자 정적 자산 경로를 설정합니다. GitHub Pages의 깊은 관리자 경로 요청은 `404.html`에서 관리자 진입점으로 복구합니다.

`main`에 푸시하면 GitHub Actions가 두 의존성을 설치하고 검증·빌드한 뒤 Pages에 배포합니다. 공개 CMS 설정은 `src/lib/cmsConfig.ts`에 있습니다. 관리자 검증용 로컬 주소에 인증 CORS를 허용했다면 작업 후 제거합니다.

최초 콘텐츠 등록은 로그인한 공식 CLI에서만 실행합니다:

```bash
cd studio
npx sanity login
npx sanity exec scripts/seed.ts --with-user-token
```

초기화 스크립트는 기존 프로젝트·프로필을 덮어쓰지 않고 누락된 기본 문구 키만 추가합니다. 인증정보를 파일·채팅·사이트 코드에 복사하지 마세요.

### 프로젝트 화면·영상

모든 프로젝트 상세 페이지는 대표 자료 → 기능별 화면 → 문제와 접근 → 개인 기여 → AI 협업 → 기술·성과·연혁 구성입니다. 자료가 없는 프로젝트는 기존 처리 흐름을 표시하며 이미지나 성과를 임의 생성하지 않습니다.

관리자 **이미지·영상**에서 프로젝트를 선택한 뒤 파일 또는 HTTPS 직접 파일 URL, 제목, 기능 설명, 화면 대체 설명을 입력합니다. 첫 자료가 대표 화면이며 **↑ 위로 / ↓ 아래로**로 순서를 바꿉니다. PNG·JPG·WebP·GIF·AVIF는 15MB, MP4·WebM은 100MB까지 지원합니다. **미리보기에 반영** 후 **발행**하면 재배포 없이 적용됩니다. YouTube 페이지 링크 대신 직접 영상 파일을 사용하세요.

파일은 로그인한 Sanity 관리자의 권한으로 기존 공개 데이터셋에 업로드됩니다. URL은 업로드 직후 공개 접근 가능하며 페이지 노출은 발행 이후입니다. **목록에서 제거**는 파일 원본을 삭제하지 않습니다. 발행 전 변경 취소는 편집 내용을 복원하며 이미 업로드된 파일은 CMS에 남습니다.

프로젝트의 media 배열은 순서를 보존하며 명시적인 빈 배열도 그대로 반영합니다. 구조 변경은 전용 편집기를 이용합니다. 미디어가 등록된 프로젝트의 보관·복원은 자료를 함께 보존합니다. seed-project-media.ts는 기존 media 필드가 없는 산재원샷에만 검토된 자료 6종을 추가하며 기존 문구·순서·보관함은 유지합니다.

파일 저장은 [Sanity 공식 자산 API](https://www.sanity.io/docs/apis-and-sdks/js-client-assets)를 사용합니다. 브라우저 코드에 쓰기 토큰을 넣지 않습니다.
